Guia de uso do continnumOS

Tudo o que você precisa para instalar, configurar e operar o continnumOS — do primeiro deploy ao atendimento em produção. Use o menu à esquerda para navegar.

Começar

O continnumOS é um CRM de atendimento via WhatsApp multi-tenant: uma única instalação atende vários clientes (tenants), cada um com dados totalmente isolados. O fluxo típico de colocação no ar:

  1. Provisione um tenant para o cliente (plano, limite de instâncias e usuários).
  2. Crie os usuários (administrador e atendentes de vendas).
  3. Conecte a instância do WhatsApp via QR Code.
  4. Importe contatos e comece a atender.
Pré-requisitos: Docker + docker-compose, um banco PostgreSQL, uma instância da Evolution API acessível e um domínio (opcional para white-label).

Conceitos-chave

TermoO que é
TenantUm cliente da sua revenda. Todos os dados (contatos, mensagens, vendas) pertencem a um tenant e ficam isolados por RLS.
InstânciaUma conexão de WhatsApp (número) vinculada a um tenant, gerenciada pela Evolution API.
Papel (role)Define o painel e as permissões do usuário: administrador ou vendas.
Super-adminQuem opera a revenda: cria tenants, define planos e acompanha billing.

Instalação / Deploy

O projeto acompanha Dockerfile e docker-compose.yaml. Configure as variáveis a partir do .env.example e suba os serviços:

cp .env.example .env
# edite .env com banco, JWT_SECRET, URL da Evolution API, etc.
docker compose up -d --build

# aplique as migrations versionadas (Alembic)
docker compose exec app alembic upgrade head
Produção: nunca deixe segredos apenas em .env plano. Use um secret manager e rotacione o JWT_SECRET periodicamente.

Acesso e login

Cada usuário acessa em /login com usuário e senha. Após autenticar, o sistema direciona automaticamente para o painel correspondente ao seu papel (Vendas ou Admin). O console é um PWA: pode ser instalado no celular e funciona com tela offline quando sem conexão.

Conectar WhatsApp

A conexão é feita pela Evolution API. Para vincular um número ao tenant:

  1. No painel Admin, abra Configurações → Instância / Evolution.
  2. Clique em Gerar QR Code.
  3. No celular, abra o WhatsApp → Aparelhos conectados → Conectar um aparelho e escaneie.
  4. Aguarde o status mudar para conectado; as mensagens passam a chegar em tempo real.
Dica: mantenha o celular com bateria e internet. Se a sessão cair, o indicador de status em tempo real avisa e basta reconectar.

Painel de Vendas

É a estação de trabalho do atendente. Principais áreas:

  • Caixa de atendimentos: lista de conversas com filtros (abertas, minhas, aguardando) e busca.
  • Conversa: histórico completo, envio de texto/mídia, respostas rápidas, encaminhamento, reações e edição.
  • Registrar venda: finalize o atendimento marcando venda/não-venda — alimenta as metas do dia.
  • Contatos e agenda: acesso rápido aos dados do cliente e agendamento de follow-up.

Contatos & listas

Gerencie a base de clientes com tags, notas e listas segmentadas. É possível importar contatos em massa a partir de arquivos .vcf. Cada contato mostra o histórico de conversas e vendas vinculadas.

Agenda

Crie compromissos e lembretes vinculados a um contato. A visão mensal destaca os dias com eventos e o sistema emite alertas dos compromissos do dia.

Chat interno

Comunicação entre a equipe sem sair do console: canais gerais e conversas diretas, com contador de não lidas e notificações. Útil para escalar um atendimento ou alinhar o time em tempo real.

Tenants & usuários

Como super-admin da revenda você provisiona cada cliente:

  1. Crie o tenant e escolha o plano (define limite de instâncias e usuários).
  2. Cadastre o administrador do cliente.
  3. O administrador cria os demais usuários (vendas) dentro do próprio tenant.
Isolamento: graças ao Row-Level Security, consultas são sempre filtradas pelo tenant do usuário autenticado. Nenhum cliente enxerga dados de outro.

Billing & planos

O módulo de faturamento controla o ciclo de cobrança de cada tenant:

  • Emissão de faturas por tenant e acompanhamento de status (paga, em aberto, vencida).
  • Integração com gateway de pagamento e webhook que marca a fatura como paga e reativa o tenant automaticamente.
  • Suspensão automática por inadimplência (past_due → suspended).
  • Portal de billing para o cliente final consultar faturas.

LGPD & auditoria

Recursos de conformidade incluídos:

  • Trilhas de auditoria de ações sensíveis.
  • Exportação e exclusão de dados por titular.
  • Política de retenção configurável.
  • DPA (Acordo de Tratamento de Dados) pronto para assinatura com o cliente.

API & webhooks

O continnumOS expõe uma API pública autenticada por token e webhooks de saída para integrar com o seu stack. Exemplo de chamada autenticada:

curl -H "Authorization: Bearer SEU_TOKEN" \
     https://SEU-DOMINIO/api/v1/contatos

Webhooks de saída notificam eventos (nova mensagem, venda registrada, fatura paga) para uma URL do seu sistema. Consulte a referência completa em docs/API_PUBLICA.md.

White-label

O sistema nasce sem referências fixas de marca. No plano White-label você define nome, cores e domínio próprio por cliente, entregando uma experiência 100% com a sua identidade. Detalhes operacionais em WHITELABEL.md.

Solução de problemas

As mensagens pararam de chegar
Verifique o indicador de status em tempo real no topo do painel. Se estiver desconectado, gere um novo QR Code em Configurações → Instância e reconecte o aparelho.
Um usuário não vê determinada aba
As abas dependem do papel e das permissões. Ajuste as permissões do usuário no painel Admin → Equipe.
Tenant aparece como suspenso
Provavelmente há fatura vencida. Assim que o pagamento é confirmado pelo webhook, o tenant é reativado automaticamente. Verifique em Billing.
